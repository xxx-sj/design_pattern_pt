# PROXY


- 가짜 대리인이 진짜 객체를 대신해서 앞에 서있는 패턴
- 진짜 객체 앞에 프록시를 둬서
  - 접근이 가능한지
  - 로그 남기기
  - 접근 제한 여부
  - 실제 객체에 접근하기 전에 해야하는 행위를 하게됨.

- 프록시 패턴에서는 프록시도, 실제 클래스도 동일한 인터페이스를 구현한다.
- 사용하는 입장에서는 진짜객체인지, 프록시인지 몰라도 된다.
  - 접근 제어
    - 민감한 객체는 아무나 접근하면 안됨 -> 프록시가 대신 gatekeeper 역할
  - lazy loading
    - 이지미가 100MB인데 매번 객체를 만들면 느림 -> 실제 접근할 때만 로딩
  - 캐싱
    - DB요청이 비싼경우 -> 프록시 객체가 캐싱 제공.
  - 로깅 / 트랜잭션
    - 진짜 객체 호출 전후에 로그/ 트랜잭션 추가하기 매우 쉬움
  - 네트워크 대역 절약
  - 비용이 큰 작업을 감추기 (원격 프록시, 가상 프록시)
    - RMI, gRPC 같은 원격 객체와 로컬처럼 통신할 수 있게 만들어줌.
